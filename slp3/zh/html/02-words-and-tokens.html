2.4 子词词元化：字节对编码

词元化是自然语言处理的第一阶段，是把连续不断的输入文本切分为词元的过程。

tokenization tokens词元化；词元把连续输入文本切分为词元的处理过程，切分所得的单位即词元，是自然语言处理流程的第一步。

我们已经见过三种词元的候选单位：词、语素和字符。但它们各自作为单位都有问题。词和语素似乎大致处于适合 NLP 处理的层级，因为它们往往具有一致的含义，但很难给出形式化的定义。字符的定义更清晰，但作为词元的单位似乎太小。

本节介绍我们在 NLP 实践中的做法：使用数据驱动的方法来定义词元，这样得到的单位通常与语素或词的大小相当，但偶尔也会用到小至字符的单位。

为什么要对输入做词元化？一个原因是，把输入转换为确定的固定单位集合，意味着不同的算法和系统能够在简单问题上取得一致。例如：这段文本有多长？（它包含多少个单位？）或者：don’t 或 New York 是一个词元还是两个词元？因此，标准化对于 NLP 实验的可复现性至关重要，本书介绍的许多算法（如用于语言模型的困惑度指标）都假定所有文本都有固定的词元化结果。

为语素和字母等更小单位也保留词元的词元化算法也消除了未登录词的问题。什么是未登录词？正如我们将在下一章看到的，NLP 算法常常从一个语料库（训练语料库）中学习关于语言的一些事实，然后用这些事实对另一个测试语料库及其语言做出判断。因此，如果我们的训练语料库包含 low、new 和 newer 这些词，却不包含 lower，那么当 lower 这个词出现在测试语料库中时，我们的系统就不知道该怎么处理它。

为了解决这个未登录词问题，现代词元化器会自动归纳出词元集合，其中包含比词更小的词元，称为子词。子词可以是任意的子串，也可以是像语素 -est 或 -er 这样承载意义的单位。在现代词元化方案中，许多词元是词，但另一些词元是频繁出现的语素或其他子词，如 -er。

这样，每个未出现过的词都可以用某个已知子词单位的序列来表示。例如，如果我们恰好从未见过 lower 这个词，那么当它出现时，我们可以把它成功切分为我们已经见过的 low 和 er。

在最坏的情况下，一个非常罕见的词（也许像 GRPO 这样的缩写词）在必要时会被词元化为单个字母的序列。

2.4.2 BPE 编码器

一旦学好了词表，就用 BPE 编码器对测试句子进行词元化。编码器只是在测试数据上执行我们从训练数据中学到的那些合并。它按我们学到它们的顺序执行这些合并（即贪心地执行，也就是从训练数据中出现最频繁的开始）。测试数据中的频率不起作用，起作用的只是训练数据中的频率。于是我们先把每个测试句子的词切分为字符。然后应用第一条规则：把测试语料库中每一处 n e 都替换为 ne，接着应用第二条规则：把测试语料库中每一处 ne w 都替换为 new，依此类推。到最后，许多合并当然只是重建了训练集中的词。但这些合并也产生了对语素的认知，例如 re- 前缀（它可能出现在 revisit 或 rearrange 这类也许未曾见过的组合中），或者不带起始空格的语素 new（因而是词内部的），后者可能出现在句子开头，也可能出现在训练中未曾见过的词如 anew 中。

当然，在实际环境中，BPE 会在一个非常大的输入语料库上执行数万次合并，从而得到 50,000、100,000 甚至 200,000 个词元的词表规模。其结果是大多数词都能用单个词元表示，只有较罕见的词（以及未知词）才不得不用多个词元表示。

至少对英语是这样。对于多语言系统，词元可能以英语为主，留给其他语言的词元更少，我们将在下文讨论这一点。

2.4.3 BPE 的实践

上面的例子只展示了从 ASCII 字节序列进行简单的 BPE 学习。那么 BPE 如何处理 Unicode 输入呢？我们通常对 UTF-8 编码文本的单个字节运行 BPE。也就是说，我们把文本的 Unicode 表示视为一系列码点，用 UTF-8 将其编码为字节，并把每一个这样的字节都当作 BPE 的输入。因此 BPE 很可能首先是重新发现了 UTF-8 用来编码各种码点的 2 字节序列和常见的 3 字节序列。同样，只在预先切分好的词内部运行 BPE 有助于避免问题。

2.8 基于规则的词元化

虽然像 BPE 这样基于数据的词元化是最常见的词元化方式，但也有一些情形我们希望把词元限制为词而不是子词。如果我们为英语运行句法分析算法、而分析器可能需要语法词作为输入，这种做法可能就有用。或者，对于任何我们已经对想研究的词元有某种先验定义的语言学应用，它也可能有用。又或者，对于把正字法词作为有用研究领域的社会科学应用，它也可能有用。

在基于规则的词元化中，我们预先定义一个标准，并实现规则来实现那种词元化。下面我们以英语的词语词元化为例来探讨。

对英语我们有一些期望。我们通常希望把标点切分出来作为独立的词元；逗号对分析器来说是有用的信息，句点则有助于标示句子边界。但我们通常希望保留出现在词内部的标点，例如 m.p.h.、Ph.D.、AT&T 和 cap’n 这类例子。特殊字符和数字需要在价格（$45.55）和日期（01/02/06）中保留；我们不想把那个价格切分成 “45” 和 “55” 两个独立词元。此外还有 URL（https://www.stanford.edu）、Twitter 话题标签（#nlproc）或电子邮件地址（someone@cs.colorado.edu）。

数字表达会带来一些麻烦；除了出现在词边界处之外，在英语中逗号还出现在数字内部，每三位数字一个：555,500.50。

词元化因语言而异；例如西班牙语、法语和德语等语言用逗号标示小数点，而在英语使用逗号的地方使用空格（有时是句点），例如 555 500,50。

2.8.1 句子切分

基于规则的切分通常用于另一类词元化过程：句子。句子切分是一个可以有选择地应用的步骤

sentence句子由若干词元组成、能表达相对完整意义的语言单位，也是句法分析等结构检测任务的处理对象。
segmentation切分按某种边界把连续文本切成更小单位的过程，如把文本切成句子或把句子切成词元。

句子切分取决于语言和体裁。对于把英语书面文本切分成句子来说，最有用的线索往往是标点符号，如句号、问号和感叹号。问号和感叹号是相对明确的句子边界标记，当它们出现时，用简单的规则就能切分出句子。

另一方面，句点字符“.”则是有歧义的，它既可能是句子边界标记，也可能是 Dr. 或 Inc. 这类缩写的标记。你刚才读到的那句话展示了这种歧义更复杂的情形：其中 Inc. 末尾的句点既标记了缩写，又标记了句子边界。因此，句子词元化与单词词元化（word tokenization）可以合在一起处理。

许多英语句子词元化方法的做法是，先判断（通常依据确定性规则，有时则通过机器学习）句点究竟属于词的一部分，还是句子边界标记。缩写词典有助于判断该句点是否属于某个常用缩写；这类词典可以手工构建，也可以用机器学习得到（Kiss and Strunk, 2006），最终的句子切分器也是如此。例如在 Stanford CoreNLP 工具包（Manning et al., 2014）中，句子切分基于规则，是词元化的确定性结果；当句末标点（.、! 或 ?）尚未与其他字符一起组成一个词元（例如缩写或数字的词元）时，句子便在此结束，其后还可选地带额外的结尾引号或括号。

2.9 最小编辑距离

我们常常需要一种方法来比较两个词或两个字符串有多相似。正如后续章节将会看到的，这在自动语音识别或机器翻译等任务中最为常见，因为我们想知道某个词序列与某个参考词序列有多相似。

编辑距离为我们提供了一种量化这类关于字符串相似度的直觉的方法。

minimum edit distance最小编辑距离把一个字符串变换为另一个字符串所需的最少编辑操作次数，操作包括插入、删除和替换。

更形式化地说，两个字符串之间的最小编辑距离定义为把一个字符串转换为另一个字符串所需的最少编辑操作次数（即插入、删除、替换这类操作）。本节将以单个词为例介绍编辑距离，但该算法同样适用于整个字符串。

例如，intention 与 execution 之间的距离为 5（删除一个 i，把 n 替换为 e，把 t 替换为 x，插入 c，把 n 替换为 u）。要看清这一点，最简便的办法是观察字符串距离最重要的可视化形式——对齐

alignment对齐两个序列的子串之间的对应关系，用于直观展示把一个字符串转换为另一个字符串所需的编辑操作。

图 2.17 展示了两个字符串之间的这种对齐。给定两个序列，对齐就是这两个序列的子串之间的对应关系。因此我们说，I 与空字符串对齐，N 与 E 对齐，依此类推。在对齐后的字符串下方还有另一种表示：一串符号给出把上面的字符串转换为下面的字符串的操作列表：d 表示删除，s 表示替换，i 表示插入。

我们还可以为这些操作分别指定特定的代价或权重。

两个序列之间的 Levenshtein 距离是最简单的加权方式，其中三种操作的代价均为 1（Levenshtein, 1966）——我们假定把字母替换为它自身（例如用 t 替换 t）的代价为零。intention 与 execution 之间的 Levenshtein 距离为 5。Levenshtein 还提出了他的度量的另一种版本：每次插入或删除的代价为 1，且不允许替换。（这等价于允许替换，但把每次替换的代价记为 2，因为任何替换都可以用一次插入和一次删除来表示。）使用这一版本时，intention 与 execution 之间的 Levenshtein 距离为 8。

2.10 小结

本章介绍了语言处理中词元与词元化的基本概念。我们讨论了词、语素和字符这些语言层级，介绍了 Unicode 码点和 UTF-8 编码，介绍了用于词元化的 BPE 算法，以及用于比较字符串的正则表达式和最小编辑距离算法。下面总结我们围绕这些概念所涉及的主要要点：

  • 词和语素是有用的表示单位，但很难给出形式化的定义。
  • Unicode 是一套系统，用于表示书写世界各语言的众多文字系统中的字符。
  • 每个字符在内部都用一个称为码点的唯一 id 表示，并可以通过 UTF-8 之类的编码方式编码到文件中，UTF-8 是一种变长编码。
  • 字节对编码（Byte-Pair Encoding，BPE）是以数据驱动方式归纳出词元的标准做法。它是大多数大语言模型的第一步。
  • BPE 词元的大小通常大致相当于词或语素，不过也可能小到单个字符。
  • 正则表达式语言是进行模式匹配的强大工具。
  • 正则表达式中的基本操作包括符号的析取（[,]、|）、计数器（*、+ 和 {n,m}）、锚点（ˆ、$）、捕获组（(、)）以及替换。
  • 两个字符串之间的最小编辑距离，是把其中一个编辑成另一个所需的最少操作次数。最小编辑距离可以用动态规划计算，计算过程同时还会得到这两个字符串的一个对齐。

历史注记

关于 Herdan 定律和 Heaps 定律的更多内容，参见 Herdan (1960, p. 28)、Heaps (1978)、Egghe (2007) 和 Baayen (2001)。

Unicode 借鉴了 ASCII 和 ISO 字符编码标准。早期的草案是在 Xerox 和 Apple 的工程师之间的讨论中形成的。一份早期的标准草案于 1988 年发布，1991 年则更正式地发布了 Unicode 标准。后来成为 UTF-8 的方案始于 1989 年的 ISO 草案，并带有各种扩展。其自同步特性是 1992 年由 Ken Thompson 与 Rob Pike 在新泽西一家餐馆的餐垫上勾勒出来的，此事颇为有名。

词的词元化和其他文本规范化算法一直被应用，从本领域诞生之初便是如此。这些算法包括词干提取，例如 Lovins (1968) 被广泛使用的词干提取器，也包括应用于数字人文的工作，例如 Packard (1973) 为古希腊语构建的剥离词缀的形态分析器。BPE 最初是 Gage (1994) 提出的一种文本压缩方法，Sennrich 等 (2016) 将其应用于早期神经机器翻译中的子词词元化。随后它被 OpenAI 的 GPT-2 (Radford et al., 2019) 采用为默认的词元化方法，也被纳入开源的 SentencePiece 库 (Kudo and Richardson, 2018)。Andrej Karpathy 有一个很好的公开实现 minbpe，网址为 https://github.com/karpathy/minbpe，他还做了一场介绍 BPE 的广受欢迎的讲座（https://www.youtube.com/watch?v=zduSFxRajkE）。

Kleene 1951; 1956 首次定义了正则表达式和有限自动机，其基础是 McCulloch-Pitts 神经元。Ken Thompson 是最早把正则表达式编译器内置到编辑器中以实现文本搜索的人之一 (Thompson, 1968)。他的编辑器 ed 包含一条命令“g/regular expression/p”，即 Global Regular Expression Print，后来演变成了 Unix 的 grep 工具。

NLTK 是一个必不可少的工具，它既提供了有用的 Python 库（https:// www.nltk.org），也在教科书 (Bird et al., 2009) 中描述了许多算法，包括文本规范化和语料库接口。

关于编辑距离的更多内容，参见 Gusfield (1997)。我们测量编辑距离的例子，即从 ‘intention’ 到 ‘execution’，改编自 Kruskal (1983)。有多种公开可用的软件包可用于计算编辑距离，包括 Unix 的 diff 和 NIST 的 sclite 程序 (NIST, 2005)。

Bellman（1984）在其自传中解释了他最初是如何想出动态规划这一术语的：

“……20 世纪 50 年代对数学研究来说不是好年头。[时任]国防部长……对“研究”这个词有一种病态的恐惧和憎恨……因此我决定改用“规划”这个词。我想传达这样一种想法：这是动态的，这是多阶段的……我想，让我们……找一个含义绝对精确的词，也就是 dynamic（动态）……不可能把 dynamic 这个词用于贬义。你试着想一个有可能让它带上贬义的组合看看，那是不可能的。因此，我认为动态规划是个好名字。它甚至是连国会议员都无法反对的。”
